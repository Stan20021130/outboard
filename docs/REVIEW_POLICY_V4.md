# v0.4：可选独立复核与 DSH 对照

日期：2026-11-03（Asia/Shanghai）。

本版将逐次强制的独立 LLM 审稿改为显式可选。源码证据、路径、范围、快照、预算检查和最终任务验收保留。实验同时比较原生直接执行、不额外评审的特调卸载、宿主强制评审的特调卸载；不使用普通 Subagent 代替原生对照。

## 调用与状态

默认 `Settings.semantic_verification=false`，MCP 调查采用 `format_version=3`，证据表结构保持不变。调查完成与独立复核状态分别报告：

```json
{
  "status": "completed",
  "verification": {
    "structure_and_citations_valid": true,
    "semantic_review_status": "not_requested",
    "semantic_support_checked": false,
    "semantic_support_passed": false,
    "snapshot_unchanged": true,
    "errors": []
  }
}
```

这里的 `completed` 表示调查者报告静态验收问题已回答，并通过程序化证据检查；未进行独立评审，不能据此声称自然语言结论已经独立认证。主 Agent 仍承担正常源码审阅、修改和最终测试。

MCP 设置 `semantic_review=true` 可为本次调查请求评审。CLI 使用 `--semantic-review`，别名为 `--semantic-verification`。Serve 启动时加该选项会对所有调查强制评审，调用参数 `false` 不能关闭宿主要求。原 `--no-semantic-verification` 继续支持，现为显式选择默认行为。

`verification.semantic_review_status` 的取值：

| 状态 | 含义 |
| --- | --- |
| not_requested | 未请求独立评审，程序化证据检查仍执行 |
| passed | 独立模型评审通过 |
| rejected | 独立模型评审指出不支持的断言或验收缺口 |
| incomplete | 请求了评审，但未完成，包括前置条件不满足、预算或接口中断 |

请求的评审未通过时，原有完成门槛保留，结果为 `partial`。默认路径仅因没有额外评审而返回 `partial` 的旧行为已移除。Patch Verifier 的必跑检查和失败复现次数未改变。

## 实验设置

运行时与驱动在模型运行前冻结，后端指纹为 `16b105bfcc9e16fc0065bbda7b414c859aa39658684a25c5fb317b5d3f9e2d0b`。全部 61 项自动化测试在正式运行前通过，不与正式模型运行并行执行。

- 模型：主 Agent、Investigator 和可选评审均为 `deepseek-v4.1-flash`，推理配置 `low`。
- 宿主：同一 DSH `0.2.1-rc.5`；每次新建会话和独立非空代码副本。
- 数据：相同 Click 提交、相同两条受控回归，复用 v0.3 的代码、任务和隐藏验收。本轮不称为新的保留任务。
- 条件：原生直接执行、默认卸载、强制评审卸载，各 4 次；每条任务各重复两次，共 12 次。两种卸载使用相同工具描述和调用指导，由宿主固定评审策略。
- 主任务预算 300 秒、500000 Token；单次 Investigator 150 秒、200000 Token。顺序轮换，所有失败、重试和回退计入。
- 最终验收使用原始测试、保留原测试语句与配置的检查，以及不提供给模型的隐藏行为验收。全部条件的验收一致。
- 源码预取、两轮补证据策略、工具后端及模型保持一致；本轮不加入并行执行或更廉价模型。

## 实测结果

12 次运行全部完成。下表保留所有样本，包括一次原生 Token 越限。Token 包含主 Agent、Investigator 及实际执行的评审；主任务时间包含冷启动、工具和任务要求的测试，最后一列另计准备与统一外部验收。

| 条件 | 最终验收通过 | 预算内成功 | 平均总 Token | 平均主任务秒数 | 含准备及外部验收秒数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 主 Agent 原生直接执行 | 4/4 | 3/4 | 377,201.50 | 130.04 | 156.61 |
| 默认卸载，不额外评审 | 4/4 | 4/4 | 269,263.25 | 147.09 | 173.06 |
| 卸载，强制独立评审 | 4/4 | 4/4 | 359,093.25 | 211.98 | 238.23 |

默认卸载相对同版本强制评审：总 Token 下降 **25.0%**，主任务耗时下降 **30.6%**，平均少约 **64.9 秒**。四个配对均更快，三个配对 Token 更低；最终验收均通过。

默认卸载相对原生：总 Token 下降 **28.6%**，主任务耗时仍增加 **13.1%**，平均多约 **17.1 秒**。四个配对都减少 Token，也都更慢。因此本版解决了默认审稿的额外开销，仍未实现相对原生“更省且更快”的目标。

### 时间与调用

| 条件 | 主 Agent 模型请求合计 | 子模型请求合计 | 每任务平均子链秒数 | 其中独立评审秒数 |
| --- | ---: | ---: | ---: | ---: |
| 原生 | 69 | 0 | 0 | 0 |
| 默认卸载 | 53 | 12 | 24.68 | 0 |
| 强制评审卸载 | 58 | 17 | 71.10 | 40.30 |

默认路径确实移除了额外模型请求，不只是修改返回标签。平均子链由 71.1 秒缩至 24.7 秒；其余流程的平均耗时也减少约 18.5 秒。日志与这个变化一致：默认结果可以交接继续实施，强制评审的 `partial` 则需要主 Agent 继续调查。但没有对每个反馈动作做独立消融，不能把全部变化都归因于单个阶段。

默认卸载的子链仍占关键路径：147.09 秒中，约 24.68 秒为子链，其余约 122.41 秒。相对原生的 130.04 秒，其余流程平均只少约 7.62 秒，仍不足抵消子链。这是下一步的效率瓶颈。

### 评审和质量的解释范围

默认组四次调查均未请求独立评审，返回的 `not_requested` 没有冒充 `passed`。强制评审组一次评审拒绝，三次未完成；三次未完成响应均报告 `incomplete`，并用满 8000 输出 Token，与输出预算耗尽一致。它们没有提供完成的审核结论，成本仍全部计入。

这比较的是当前评审实现及其回退开销，不能推论更高效、能正常完成的独立评审也没有价值。本轮没有独立标注每条未评审自然语言结论的准确率；最终测试全过不等于调查报告的所有解释均正确。

### 缓存和金额

下表为每组四次合计，缓存输入不重复加入总输入，输出已包含推理 Token。

| 条件 | 缓存输入 | 未缓存输入 | 输出 | 总 Token |
| --- | ---: | ---: | ---: | ---: |
| 原生 | 1,388,800 | 94,294 | 25,712 | 1,508,806 |
| 默认卸载 | 856,320 | 192,016 | 28,717 | 1,077,053 |
| 强制评审卸载 | 1,123,968 | 242,126 | 70,279 | 1,436,373 |

相对强制评审，默认卸载的三个计量类别均下降；在相同、非负的分项 Token 单价下，推理费用方向也是下降，但没有代理单价，无法给出实际金额或金额比例。相对原生则存在缓存输入下降、未缓存输入和输出上升的交换，不能把总 Token 下降直接换算成账单下降。

### 预算异常及敏感性检查

原生 `default-map-none-impact-r1` 在最后一个请求前累计 484901 Token，该请求消耗 42308，合计 527209，超过配置上限 500000 共 27209。现有透明账本在请求前检查已消耗量，因此允许最后一笔越限；本轮不能声称每次实际消耗都严格处于相同上限内。

该样本的原始记录、验收通过及越限标记全部保留，没有重跑或替换。`summary.json` 中 `main_task_successes` 是最终验收通过数，`successes` 还要求预算合规，所以原生分别为 4 和 3。

另对三组均预算合规的三个匹配任务样本做敏感性检查，不替换上面的全部样本均值：

| 条件 | 配对数 | 平均 Token | 平均主任务秒数 |
| --- | ---: | ---: | ---: |
| 原生 | 3 | 327,199.00 | 130.99 |
| 默认卸载 | 3 | 247,055.67 | 141.61 |
| 强制评审卸载 | 3 | 372,565.67 | 210.06 |

结论方向保持一致：默认卸载比强制评审快，仍比原生慢；最终验收相同，但样本不足以建立统计非劣结论。

## 工程校验与限制

- 61 项自动化测试通过，覆盖默认不评审、按次请求、宿主强制评审、拒绝和中断状态，以及原有证据、越界、快照、时间、Token 与执行检查。
- 主 Agent 的 DSH 用量与透明账本按主角色核对，子 SDK 用量与子角色账本另行核对，全部一致。
- 三组实际评审策略与冻结配置一致，所有子链快照保持不变，原测试没有被同名定义覆盖，全部导出的 Patch 可应用。
- 当前源码与冻结源码、驱动指纹一致；没有为了得到正面结果改变运行中的后端。
- 数据来自一个仓库两条已使用过的受控回归，每条两次重复；B、C 被要求卸载，不能据此证明自主选择策略或跨仓库泛化。
- 单机与提供方缓存未清空，也未隔离其他系统负载；时间只作探索性观察。本轮自动化单测在正式实验前完成。
