# v1.4：DSH 原生主 Agent 与特调卸载对照

日期：2026-11-03。单次受控对照中，**回归测试构造与差分验证的卸载组更慢、Token 更多；多失败归并的卸载组更快、Token 更少**。两个场景的两组都通过了预设的独立验收，但多失败场景的原生组还提供了更多源码和复现证据，不能仅凭验收通过就宣称输出质量完全相同。

## 结果

每个场景各有一次原生执行和一次此前记录的卸载执行。时间是 DSH 主任务墙钟，包含模型、工具及任务内运行的测试，不含任务准备和独立验收。

| 场景 | 方式 | 最终独立验收 | 输入 Token | 缓存输入 | 输出 Token | 总 Token | 模型请求 | 主任务秒数 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 回归测试构造与差分验证 | 原生主 Agent | 通过 | 110,601 | 98,176 | 2,367 | 112,968 | 11 | 78.797 |
| 回归测试构造与差分验证 | 特调卸载 | 通过 | 136,889 | 113,536 | 7,126 | 144,015 | 17 | 143.312 |
| 多测试失败归并 | 原生主 Agent | 通过 | 210,623 | 189,312 | 6,116 | 216,739 | 15 | 114.282 |
| 多测试失败归并 | 特调卸载 | 通过 | 53,511 | 41,856 | 5,557 | 59,068 | 7 | 73.469 |

| 场景 | 总 Token | 输出 Token | 主任务墙钟 |

缓存输入是输入的子集，不能重复加入总量。输出包含推理 Token；未获得实际单价，不能报告金额。两项任务中，卸载与原生的缓存输入、未缓存输入、输出分别均朝总 Token 相同方向变化；若两组采用相同的非负分项单价，且至少一项单价非零，模型 Token 费用方向也相同。

## 任务、控制与限制

- 使用相同 DSH 0.2.1-rc.5、`deepseek-v4.1-flash`、`low` 推理、300 秒及 500,000 Token 预算。两组的请求和响应模型均核对一致，全部推理请求有 usage。
- 两组使用同一批 Click 受控缺陷，原生副本的起始源码快照与卸载组调用时的快照逐一一致，使用相同外部验收。原生组不加载卸载工具；卸载组由提示要求调用指定工具，不能证明自主选择卸载。
- 原生组是在看到先前卸载结果后补充的，没有随机交错运行；提供方缓存和本机负载也未隔离。每组每项只有一次，结果属于探索性观察，不能估计稳定收益、统计质量非劣或跨任务泛化。
- 两组遵循相同任务目标与结果验收。回归场景的原始卸载工具执行了修复前后差分；为对齐实际验证工作，补充原生任务明确要求先跑缺陷状态、再跑修复状态。两组系统提示因此存在必要的执行方式差异，并非逐字相同。

## 回归测试构造与差分验证

两组都完成源码修复，新增测试，并通过同一独立验收：原缺陷和两个针对性缺陷变体均被新测试检出，修复后通过；原有测试和配置保持不变；外部非 stress 测试为 2181 passed。

卸载组第一次因主 Agent 交接的 Diff 行数不正确而被拒绝，第二次返回 `partial`，其两条测试的修复前后差分通过；`partial` 的未解决项涉及任务范围之外的嵌套前缀。两次调用均计入总耗时。第二次 Subagent 调用使用 6 次模型请求、27,463 Token、48.328 秒。提交阶段有 3 次响应产生了 4 个当前不可用工具调用，日志记录这些响应共 12,777 Token、代理响应时间约 6.14 秒；不能仅据此确定根因或假定全部可省。

从 Token 分解看，原生为未缓存输入 12,425、缓存输入 98,176、输出 2,367；卸载为 23,353、113,536、7,126。卸载输出约为原生的 3.01 倍，其中主 Agent 输出 3,510、Subagent 输出 3,616；输出 Token 数增加，但没有逐 Token 的生成时间，不能精确分解其对墙钟差异的贡献。

最初还运行了一次未在任务内明确要求修复前测试的原生对照，结果为 73,044 Token、73.672 秒，并通过相同外部验收。该次原生轨迹先修复再运行新测试，因此作为保留的辅助记录，不用于上表的差分验证工作量对照；没有删除或重跑它。

## 多测试失败归并

输入为三条真实 pytest 失败；受控验证表明其中两条源自前缀归一化缺陷，第三条源自整数开区间 clamp 缺陷。两组都在结构化报告中将预设二元组归为可能相关，指出第三条不同，并保留不确定性，因此通过预设验收。

两条轨迹提供的证据范围不同：卸载组依据给定日志提出假设，未复现测试或检查源码；原生组复现了失败、检查了相关源码、运行完整测试，并额外发现两条同类范围计算失败。后者提供的信息更丰富，且付出了额外时间和 Token；任务本身没有要求全量测试。因而本次数据支持“较窄的三条失败归并任务在这一次卸载中更省、更快”，不支持在同等完整诊断证据下仍有相同收益。

原生为未缓存输入 21,311、缓存输入 189,312、输出 6,116；卸载为 11,655、41,856、5,557。卸载的输出仅降低 9.14%，总 Token 的主要下降来自输入。卸载子链输出 3,321 Token，其中 2,840 是包含在输出中的推理 Token。
