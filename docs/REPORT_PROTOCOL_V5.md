# v0.5：交接报告与工具 Schema 优化

日期：2026-11-03（Asia/Shanghai）。

本轮针对 Investigator 最终报告的输出开销，以及取证转入汇总时工具列表变化带来的缓存机会。底层模型、推理配置、两个取证轮次、源码检查和最终任务验收保持一致。是否采用某项优化，以本轮消融和原生主 Agent 对照为准。

## 两项改动

`compact_report` 控制模型内部的提交格式。模型保留所有实质结论、关系、测试行为、逐项验收引用及未解决问题；引用写为 `"E3"`。Runtime 从已观察的证据表补路径、行号和原文，并生成重复元数据：

- `summary` 取第一条 finding 的 claim，作为预览。
- `criteria_coverage.explanation` 提示查看已列出的条目和未解决问题，不生成新的解释性断言。
- `related_tests.path` 取该条首个证据的路径；提交协议要求先引用主要测试文件。

该格式不是任意截断报告。未覆盖的验收条件仍须标为未解决；未知证据 ID、越界引用、无效条目索引、未读源码和源状态变化仍不能通过检查。旧的完整报告在兼容入口继续接受。

`stable_tool_schema` 使取证和最终汇总请求携带相同的工具定义和顺序。最终轮仍强制选择 `submit_investigation`。即使接口忽略强制选项并返回新的读取或执行调用，Runtime 也会拒绝该调用，而不会继续读取或运行检查。缓存收益依赖实际服务，不能仅从 Schema 稳定推断。

两项都是模型内部协议调整。MCP 公开结果仍为 `format_version=3`，引用表和完成／复核状态不变；CLI 和 Python 仍返回展开的证据。默认不额外评审的 v0.4 策略继续使用，按需评审与宿主强制评审继续支持。

本轮选定 `compact_report=false, stable_tool_schema=true` 为默认。精简提交通过 `--compact-model-report` 显式启用，`--full-model-report` 选择默认完整提交。`--dynamic-tool-schema` 关闭稳定工具列表。原生修复评测会把这些开关传入 MCP 子进程，避免评测配置与实际执行不一致。

日志增加逐次请求序号、工具 Schema 哈希、强制工具、请求耗时，以及取证／报告／评审用途。`request_seconds` 包含接口等待和响应传输，不称为纯输出生成时间；输出 Token 仍含模型报告的 reasoning Token，不重复计费。

## 实验方法

开发回放采用 2×2 消融：完整／精简提交 × 动态／稳定工具 Schema。两条旧任务各重复两次，共 16 次；任务 Capsule、源码快照、模型和预算相同，顺序交叉平衡。纠正调用、未完成报告和失败全部保留。该回放比较执行器配置，不能替代原生主 Agent 对照。

完整流程用 DSH `0.2.1-rc.5`，比较原生主 Agent 直接执行和选定配置的特调卸载。共两条任务，每条重复两次，每组 4 次：

- 旧任务：Click 自动环境变量前缀的连字符归一化回归。
- 新任务：Click 多值参数环境变量拆分回归，覆盖固定及变长 nargs、带空格的单值、显式环境变量列表回退、自定义拆分器、命令行优先级及 Option 行为。

新任务在组件调优前冻结，变异版本的可见回归和隐藏检查均失败，正确上游版本均通过。它是人工构造的受控回归，并非随机抽取的真实历史 issue。模型运行看不到隐藏检查、其他检出或评测驱动。

主 Agent 和子 Agent 均使用 `deepseek-v4.1-flash`、`low`，保留相同的原生文件工具权限及最终测试要求。两组均使用新建的非空代码副本。卸载组的主 Agent 必须在编辑前调用 Investigator；普通 Subagent 不作为原生对照。

总账包含主 Agent 和子 Agent 的输入、缓存输入、输出、纠正、回退和集成；墙钟包含宿主启动、工具执行和主 Agent 自己的最终测试。另报告外部验收耗时。最终质量采用原始测试 AST 和配置保护、原始完整非压力测试套件及隐藏 oracle；新增合法测试可保留，但不能覆盖或替代原测试。

保持历史预算：主任务 300 秒、全链 500000 Token，单次调查 150 秒、200000 Token，单请求输出上限 8000。代理在请求前检查累计用量，最后一次请求可能跨过总预算；此类运行保留，并单列为预算不合规，不补跑替换。

## 开发回放结果

每组 4 次，均保留部分完成报告及纠正调用。下表的“完整回答”只表示静态调查问题均有报告、且通过程序化检查，不能代替语义认证或最终修复成功。

| 模型提交／工具 Schema | 完整回答 | 平均模型调用 | 平均总 Token | 平均输出 Token | 平均调查耗时（秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 完整／动态 | 2/4 | 3.5 | 43586.00 | 4278.75 | 27.867 |
| 精简／动态 | 2/4 | 3.5 | 43568.75 | 4580.50 | 32.493 |
| 完整／稳定 | 2/4 | 3.0 | 36748.25 | 3566.00 | 23.184 |

选定的完整／稳定配置相对完整／动态，平均调查耗时低 16.8%、总 Token 少 15.7%、输出 Token 少 16.7%。报告尝试的平均输出为 3087.75 Token（对照 3681.25），其 API 请求耗时为 15.363 秒（对照 18.382）。缓存占输入比例为 26.7%（对照 21.7%）。路径选择、提前汇总和协议纠正次数也改变，因此这些收益不能全部归因于缓存或 Schema 稳定本身。

精简 Schema 并未稳定减少模型输出：模型仍可能输出过多引用而触发纠正，也可能花更多 reasoning Token。完整／稳定没有减少本轮完整回答次数；精简／稳定还出现额外的未完成报告，因此未作为默认。两条 default-map 回放在四种配置下均存在未解决问题，未把它们删出统计，也未用更容易的问题替代。

四组出现的协议／证据纠正次数依次为 2、2、1、4。精简／动态的非 reasoning 输出虽从平均 2857.25 降至 2434.00 Token，但 reasoning 从 1421.50 增至 2146.50，最终总输出反而增加。精简／稳定还出现过多引用、非法枚举值、JSON 语法及包裹层错误。所有纠正过程均保留在日志并计费，没有通过放宽校验将它们视为成功。

## 为什么局部回放改善，完整流程仍变慢

主 Agent 自身的平均输出只从 6127.25 降至 5802.50 Token，减少 5.3%；子 Agent 每次平均新增 5288.00 输出 Token，总输出因此增加 81.0%。主 Agent 自身累计 Token 也没有减少，反而增加 1.5%，峰值输入增加约 0.9%。本轮连“节省主 Agent 上下文”的效果也不稳定。

四个调查共用 16 次模型调用，其中 8 次取证、8 次报告尝试。实际只需要交接四份报告，协议／证据错误额外触发了四次纠正。最终报告尝试占子 Agent 输出的 90.1%，API 请求时间为 86.484 秒，占其模型请求时间 115.000 秒的 75.2%。这是请求耗时，不是单独的输出生成时间。默认已经没有独立 LLM 审稿；这些额外调用来自调查报告自身的纠正，而不是额外评审。

四份调查报告只有一份完整完成、三份返回 `partial`，主 Agent 仍继续补证据、修改和验证。部分报告没有被算作成功调查。部分完成不直接等于最后修复失败，但其交接和后续工作均进入总账。

主 Agent 的可见 pytest 执行还存在差异：原生共跑 4 次完整套件、9 次聚焦检查，卸载共跑 6 次完整套件、10 次聚焦检查。日志中的 pytest 自报时间平均为 22.083 秒与 40.058 秒。两个卸载样本先跑完整套件，再追加测试、修正测试后重跑完整套件；这些耗时保留。少做验收不是本版的优化方法，更合适的后续方向是安排好调查、修改、新增测试和最后完整回归的顺序。

全部 API 请求时间平均从 48.338 秒增至 72.680 秒。剩余墙钟还包含进程启动、工具、上下文构造和交接，不能仅用输出 Token 解释全部耗时。开发回放的收益也包含随机路径选择、提前汇总和较少协议纠正，不能外推为完整链条收益。

## 结论与验收记录

保留完整报告＋稳定工具 Schema 作为当前调查器的候选默认配置，精简模型报告仍需显式启用。它在本轮开发回放优于动态 Schema 配置，但**本轮没有证明主 Agent 将这两类修复任务卸载后更省或更快**。强制卸载实验不代表主 Agent 的自主调用策略；也不支持扩大默认卸载范围。

缓存输入、未缓存输入、输出三个计费桶本轮均增加。因此，在两组使用相同正 Token 单价的假设下，费用也会增加；没有真实分项价格或账单，报告不提供实际金额。两个场景、每组四次不足以证明统计质量非劣，也不能把本轮与 v0.4 的不同任务组合直接作版本因果比较。

发布代码在正式模型运行前通过 67 项测试，记录于 `.trajectory/report-schema-optimization/unittest-release-v5.txt`。源码和驱动在正式运行中保持冻结；全部主／子用量核账一致、模型与推理配置一致、原生没有额外委派、子 Agent 每轮工具 Schema 一致、取证没有超过两轮、源码快照不变。8 份补丁均可应用，原始测试 AST 和配置保留，也未用同名定义覆盖原始测试。

原始结果为 `dsh-v5/summary.json`，补充核账与保护检查为 `dsh-v5/analysis.json`，后者由 `benchmarks/report_protocol_analysis.py` 从原始日志生成，不改写任何 `result.json`。后续调优应优先减少报告协议纠正和交接后的重复工作；继续堆叠委派提示或仅缩短 Schema 没有得到完整流程的正面证据。
