# DSH 主 Agent 直接执行与特调卸载：验证协议

冻结日期：2026-11-02。正式运行前记录任务集、顺序、预算、代码指纹与依赖锁文件。

## 问题和比较对象

比较同一 DSH 主 Agent 直接完成完整任务，与该主 Agent 使用指定特调 Subagent 后继续完成完整任务。没有普通 Subagent 组。

本轮先测受控卸载机制：B 组的宿主指导要求在指定环节调用对应工具至少一次。它不评价主 Agent 是否会自主选择有利的卸载机会。A 组保留 DSH 原生读取、搜索、编辑、PowerShell 和测试能力；两组都禁用原生子 Agent、额外委派、网页检索和无关用户 Skill 发现。

## 固定条件

- 宿主：本地安装的 DSH 0.2.1-rc.5；本次安装 package-lock.json 保存全部解析依赖。
- 模型：deepseek-v4.1-flash；两组及 Subagent 使用同一用户指定网关 http://127.0.0.1:8788/v1，Responses 协议，low 推理配置，单次输出上限 8000。
- 目标：[pallets/click](https://github.com/pallets/click)，上游提交 2247b35ea1c47c727d7a06e51fa280e12a863ff6。
- 获取：本机 git HTTPS 握手失败，改从 GitHub codeload 按提交获取源码归档，记录归档 SHA256；每个实验起点另建仅含缺陷状态的本地 Git 仓库，避免历史直接泄露修复。
- 环境：Python 3.12.15，pytest 9.2.0，Click 8.6.0.dev0，PYTHONPATH 优先使用各工作副本的 src。
- 工作区：每次运行使用独立、非空的源码副本和独立 DSH_HOME。完整任务委托在 A/B 间相同，B 的工具和调用指导属于处理条件。
- 权限：本机 DSH 的 Windows workspace-write ACL 初始化失败；正式两组统一使用 danger-full-access。只对受信任代码做本地测试，源码副本不被表述为 OS 沙箱。接入失败探针单独保存，不混入正式效果。
- DSH 遥测和会话上传关闭，不修改用户全局配置。

上游在正确仓库工作目录中通过 2178 项测试，108 项跳过、31000 项 stress 用例按项目默认规则排除、1 项 xfail。最初从外部工作目录运行出现的 glob 路径失败属于接入检查，已纠正 cwd，不作为仓库回归。

## 任务

这是“真实仓库 + 受控回归”，不等同于真实历史 Issue 的随机样本。每项加入一个向两组公开的最小复现测试，另有不传给模型的行为验收脚本。缺陷前的上游通过隐藏验收，受控缺陷状态不通过；不因正式结果调整任务或编排。

| 任务 | 完整委托 | B 组卸载 |
| --- | --- | --- |
| env-prefix-impact | 修复带连字符的自动环境变量前缀归一化，保留嵌套命令和显式参数行为，分析影响并验证 | change_impact 调查 |
| open-range-diagnosis | 诊断并修复整数开区间 clamp 回归，保留闭区间、报错及 FloatRange 约束 | diagnose_failure |
| unicode-choice-verification | 评估提供的候选 Patch，修复不区分大小写的 Unicode Choice 回归，保留原始对象和 Enum／上下文语义 | verify_patch |

每项 2 次重复，A/B 次序按任务和重复交错，共 12 次。模型不会获得受控变更规则、隐藏验收或正确源码位置；第三项的候选 Patch 是双方都有的用户输入。

## 预算和计量

- 主 Agent 进程墙钟上限 300 秒；通过统一 API 账本在累计已知 500000 Token 后拒绝下一次模型请求；不声称能事先精确限制一个尚未结束的响应。
- 单次 Subagent 上限 150 秒、200000 Token，保留原有引用、语义复核和快照验证。
- 每个必跑检查有固定参数数组和超时；模型不能改检查命令。全套默认非 stress 回归与聚焦测试均保持。
- 每次模型调用通过透明 HTTP 转发记录原始接口 usage、模型、推理配置和时间；不修改请求体或响应内容。主／子请求独立标记，以接口 total_tokens 合计，缓存 Token 单列。
- DSH 的 inputTokens 不包含已单列的缓存输入，不能简单以 inputTokens+outputTokens 代替真实总量；同时保存 DSH step 总量用于交叉核对。
- 无定价则不报告实际金额收益。没有返回 usage 的调用标记统计不完整，不计成零成本成功。
- agent_wall_seconds 包含 DSH、MCP 冷启动及主任务执行；end_to_end_seconds 再包含每次工作副本／配置准备和独立最终验收。安装依赖的一次性成本不摊入单次任务，另行披露。
- 所有模型、复核、失败、重试、未调用和超时都保留，不只统计成功卸载。

## 验收与解释

主任务成功由独立进程执行完整原始测试与隐藏行为验收决定，既有测试和项目配置不能修改。另记协议合规：B 是否实际调用指定执行器、A 是否保持直接执行；不隐去代码成功但未发生卸载的情况。

报告所有任务结果、主／子／合计 Token、调用次数、冷启动时间和最终验收时间。配对比较包括未成功运行；另列双方都成功时的效率观察，不能据此声称总体成功率相当。

由于只有 3 项受控任务、每项 2 次重复，没有足够依据证明统计质量非劣或推广到跨仓库、长历史、自主卸载及真实金额收益。正面或负面结果均应按此范围解释。第一轮不根据结果修改 Subagent Prompt、工具、预算和策略。

## 复现入口

实现位于 [dsh_study.py](../benchmarks/dsh_study.py) 与 [dsh_mcp.py](../benchmarks/dsh_mcp.py)。本机冻结清单位于 .trajectory/dsh-study/manifest.json，包含任务、复现、独立验收、缺陷起点、执行顺序和文件指纹。正式记录位于 .trajectory/dsh-study/runs，每次保存事件、API 账本、源码改动、回归和验收结果。

```powershell
uv run python benchmarks/dsh_study.py prepare
uv run python benchmarks/dsh_study.py run
```

依赖安装、源码获取和权限探针为独立准备阶段；上述命令假设本机准备目录已存在，未尝试自动管理用户全局 DSH。

## 执行期间的评估器修正

首次直接执行在现有测试文件中新增函数，未改原测试，却被初始字节级文件比较误判。原始评分保留，所有运行统一增加 AST 语句保留检查；需要复核的源码使用新副本中的原始测试和隐藏行为验收评判。没有重新请求 Agent、改变任务或调整 Subagent。此项运行中修正应与探索性结论一起披露。

主任务墙钟保持原测量值；涉及事后复核的准备加验收时长，以统一验收工作量替换初始误判的验收工作量，不包含事后排队和修正评估器的等待。最终报告区分这两种计时。
